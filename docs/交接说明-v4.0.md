## 二、数据流与联动关系（重要）

- **解析管线**：`doParse` → 大数据（>2 万行）走 `LabEngine.parseAsync`（Worker），小数据同步；解析完成后 `afterParse → refreshDerived` 在主线程统一计算统计/结论（口径切换/合并/换算共用同一后处理，Worker 只承担 parse）。
- **采集联动链**：`setupSerial.handleLine` 每 150ms → `updateLiveChart` → `updateSerialMetrics` → **`LabDashboard.update(liveSeries, liveKeyOrder, spikeKeysNow())`** → **`LabBench.updateFromSeries(...)`**（实验台打开时）。两个消费方都吃同一份 `liveSeries`（key → {label, data:[{x,y}]}）。
- **3D 场景数据源**：galaxy 直接读 `state.ds`（含 outliers Set 与 state.events 石碑）；bench 读采集的 liveSeries。两个场景退出时都销毁 renderer 与监听，不影响主图实例。
- **指纹与分享**：指纹输入 = `原始数据文本 + JSON.stringify(state.ops)`（顺序敏感）；分享 payload = {text, opts, reportInfo}。两者都以 `state.pending.text` 为数据源头，Excel 来源（aoa）没有原始文本，指纹/分享会提示改用复现包或重新导入。

## 三、各模块注意事项（接手前必读）

1. **engine-worker.js 用 importScripts('parser.js')**——Worker 的相对路径基于 worker 脚本 URL，所以三个文件必须在同一目录（当前都在 src/ 与 dist/ 各一份，OK）。
2. **file:// 下 Worker 自动回退**：`LabEngine._workerBroken` 置位后本会话不再尝试 Worker。部署环境（http/https）Worker 正常生效。
3. **galaxy/bench 每次打开都新建 renderer**，退出时 dispose + 移除 overlay + 移除监听；不要在页面里同时开两个（互斥由 st 单例保证）。
4. **虚拟仪表盘按通道序号分配仪表类型**（第 1 通道温度计、第 2 表盘、第 3 数码管），通道语义未知时用的是滑动范围归一化，不是物理量纲——改仪表语义时改 dashboard.js 的 build/update 函数对。
5. **复现包指纹与"只算当前指纹"的输入必须一致**：都用 `rawTextOf()`（pending.text，Excel 用 aoa 转 TSV）+ `state.ops`。如果以后改流水格式（pushOp 的文案格式），指纹会全量变化——属预期，验证双方用同一版本即可。
6. **three.min.js 用 r149 UMD**（全局 THREE），不要混用 ESM 版本。
7. **对比组列序错位（v3.0 遗留 P1）已修（2026-11-21 验收轮）**：renderCompareCols 的 option value 改为存列名，renderCompareChart 每组按 `ds.columns.find(c => c.name === colName)` 取各自 index。实测 A 组 temp/humi/press、B 组 humi/temp/press，选 humi → A 首点 61.98、B 首点 70.0（修前 B 得 30）。同期修掉两处：仪表开关 `dashOn` 跨函数不可见（改 state.dashOn）、galaxy.js 用 `window.state` 读写 hunterVerdicts（state 是顶层 const，改 `typeof state !== 'undefined'` 探测）。

## 1. Welch t 检验（组间差异显著性）

- **入口**：多组对比卡（组数 ≥2 时自动算前两组），结果同时存 `state.compareTTest`；生成报告时经 `setupReport` 的 `info.tTest` 传入，report.js 在「数据结果」节尾部自动追加一段。
- **实现**：`LabAnalysis.tTestWelch(a, b)`（analysis.js）。p 值 = `I_{df/(df+t²)}(df/2, 1/2)`，不完全贝塔用连分数法（betacf），ln B 用 Lanczos log-gamma。**注意**：初版把 ln B 的符号写反导致 p 虚大，已修正——如再动这段，先用已知值回归：df=23、t=8.63 → p≈1.1e-8；两组同均值 → p≈0.7。
- **限制**：只对比前两组。三组以上要做两两比较 + Bonferroni 校正，留待下批。

## 2. 传感器驱动包

- **入口**：工具箱 C 代码卡「下载驱动包 (.zip)」→ `genDriverPackage()`（app.js）。
- **产物**：`{ntc_b|ntc_sh|adc_volt|poly_conv}-driver.zip` = sensor.h（参数宏 + include guard + 声明）+ sensor.c（实现引用宏）+ driver.md（模型/接线/示例/换算记录快照/参数指纹）。
- **设计要点**：参数全部宏化在 sensor.h——换标定只改头文件；NTC B 值式额外生成 21 点分度表 + `ntc_temp_lut()` 查表插值版（无 math.h）；指纹复用 `LabRepro.fingerprint`（输入 = 参数 JSON + calibLog 的 formula 列表），与复现包同源算法。
- **依赖**：JSZip（已在 vendor）。

## 3. 实验知识卡

- **入口**：页签栏右侧「📖 实验知识」→ `setupKnowledge()`（app.js 的 KNOWLEDGE 对象 + know-overlay 弹层）。

# v4.2 增量交接（ZCode 第三批，2026-11-22：电路仿真页）

> 本批一个旗舰功能：**第八页签「电路仿真」**（方案 X 第一版，调研依据与分层路线见 CHANGELOG v4.2 节头部）。改动文件：新增 `src/sim.js`（约 900 行）；`index.html`（页签按钮 + #tab-sim 区块 + sim.js 引入）；`app.js`（setupSim 约 80 行）；`style.css`（.sim-* 约 170 行）。无新 vendor。

## 1. 架构与数据流

- **元件注册表** `LabSim.PARTS`：type 名与 Wokwi 一致（wokwi-led / wokwi-resistor / board-esp32-devkit-c-v4…），每个元件定义引脚相对坐标表。加新元件 = 在 PARTS 加一项 + renderPart 的视觉分支。
- **电路状态** `LabSim._st()`：parts / conns / nets / netOf / netLevels / rules / wave / serial。
- **网络解算**：连线把引脚聚成网络（并查集）；网络电平 = 强驱动（GND=0、3V3=1、GPIO 输出）> 上拉 > 悬空；**元件内部导通桥**（电阻/NTC 两脚、按钮按下、开关拨通）把两侧网络电平合并——注意 netOf 现在登记每个引脚键 → 网络号（v4.2 修复）。
- **MCU 规则引擎** `st.rules`：GPIO → {mode: high/low/toggle/pwm-breath/input-pullup/input, period}，applyRules 每帧写 esp.outputs。**故意无代码执行面**（安全基线）；Serial.print 类需求等方案 Y。
- **波形与导出**：recordWave 每 20ms 帧记录网络电平（600 帧滑窗）→ renderScope 画轨迹 → `exportToAnalysis()` 组 CSV → `state.pending` + doParse → 进分析链路。**这是本页存在的理由**，别拆。

## 2. 接手注意

1. **netOf 全量映射**：netOf.get(任意引脚键) 都返回网络号（v4.2 修复后）。不要再"只登记根"。
2. **fullRender 保留 #sim-wires**：清空画布时不能把连线 SVG 容器一起删（曾致连线消失）。
3. **tickLoop 有 try/catch**：运行异常写进 sim-serial 事件日志并自动停止——排查仿真问题先看那里。
4. **桥接 merge 用 reduce** 合并 drivers（曾因 strong[1] undefined 抛错）。
5. **file:// 缓存坑**：改 sim.js 后浏览器可能加载旧版，index.html 里 script 带 `?v=NNN` 参数，改一次升一号。
6. **占位与路线**：LCD1602 是 I2C 占位（脚本 API 驱动待方案 Y）；电位器/NTC 的模拟值进 ADC 的路径待接 MicroPython；ESP32 指令级仿真 = 方案 Z（espressif/esp-qemu WASM 化，长期）。
7. **diagram.json 兼容**：导入吃 Wokwi 项目文件；导出可直接粘回 Wokwi。type 名映射在 PARTS 注册表——Wokwi 新元件要补注册表项 + 视觉分支。

# v4.3 增量交接（ZCode 第四批，2026-11-22：方案 Y Python + 方案 Z 手册）

> 本批两件：**方案 Y**（仿真页 MCU 双模式——新增 Python 脚本执行）与 **方案 Z 实施手册**（docs/方案Z-esp-qemu-wasm.md，未实施，属环境工程）。
> 改动文件：新增 `src/sim-py-worker.js`（Pyodide Worker + machine 模拟层）+ `vendor/pyodide/` 5 文件（13MB）；`src/sim.js`（pyMode/pyPinWrite/pyInputsSnapshot/pyPrint/电位器 SIG analog）；`src/index.html`（MCU 模式切换 + Python 面板 + script 版本参数）；`src/app.js`（setupSim Python 段约 100 行）；`src/style.css`（.sim-mcu-mode/.sim-py-*）。

## 1. Python 模式架构（与规则引擎的关系）

- **MCU 模式切换**：规则引擎（默认）/ Python 脚本。`LabSim.setPyMode(true)` 后 applyRules 跳过——MCU 输出由 Worker 的 machine 层驱动；渲染循环（solveAll/示波器/波形）不变。
- **Worker**（sim-py-worker.js）：加载 Pyodide → 注入 machine 模拟层 → 跑学生代码（阻塞 worker 无妨）。双向桥：
  - 出：pin/pwm/print/status/error → 主线程 pyPinWrite / pyPrint（串口数组）
  - 入：每 100ms 推送输入快照（digital: GPIO 电平；analog: 电位器 SIG）→ Worker 端 `inputs` 缓存 → Python analogRead/pinRead（滞后 ≤100ms）
- **诚实定位**：Pyodide = CPython 3.12 WASM，machine 是语义模拟层（接口与真板一致），**不是 ESP32 固件**——学生代码语法原样可跑，真固件执行见方案 Z 手册。

## 2. 接手必读（四个踩过的坑）

1. **print/status 必须 pyPrint 进 LabSim 串口数组**——直接写 DOM 会被 renderSerial 每帧覆盖（症状：消息"消失"）。
2. **桥函数不能带双下划线**——Python 类方法内 `_js.__simPinWrite` 会被 name mangling 改写成 `_Pin__simPinWrite`（AttributeError）。已改名 simPin* 并逐个挂 worker 全局。
3. **machine 必须注册模块**：types.ModuleType('machine') + sys.modules——否则 `from machine import Pin` 报 ModuleNotFoundError。
4. **file:// 不支持**：Worker/WASM fetch 受限——Python 模式需 http（本机 `python -m http.server 8123`）或部署环境；UI 已做提示。
5. **脚本版本号**：index.html 的 script 引用带 ?v=NNN，改 JS 一次升一号（http 缓存坑，v4.2 已记）。
6. **「Python 约 13s 后停止」已定位并修复（2026-11-22 DSH 验收轮）**：不是 Worker 挂了，是两个独立根因——① `tickLoop` 用 `requestAnimationFrame` 驱动，窗口不可见时 Chrome 把 rAF 节流到 ~1 fps，而每帧只 `st.tick++` 一次、时间却按 20 ms/帧换算，仿真时钟被拖慢 50 倍，看起来像停了（实测 setInterval(20ms) 1.5 s 跑 80 次、rAF 只 3 帧）；② `simSleep` 在 Worker 内忙等，期间不消费 postMessage，主线程每 100 ms 推的 `{cmd:'inputs'}` 全被丢弃，Python 侧 ADC/Pin 读数冻结在启动那一刻。修法见下节「v4.3 验收修复」。

## 3. Pyodide 文件与部署

- vendor/pyodide/：pyodide.js(14.7KB) / pyodide.asm.js(1.2MB) / pyodide.asm.wasm(10MB) / python_stdlib.zip(2.3MB) / pyodide-lock.json——**部署时整目录上传**，wasm 可预压缩 gzip（10MB→约 4MB）。
- Worker 内 `loadPyodide({indexURL})` 的 indexURL 由主线程传入（'vendor/pyodide/'），Pyodide 会按它加载 asm.wasm/stdlib。

## 4. 方案 Z（未实施）

见 docs/方案Z-esp-qemu-wasm.md：四步路线 + 风险表 + 验收标准。要点：espressif/esp-qemu（GPL）emscripten 编译 WASM 是唯一真固件路线；需要 Linux/CI 构建环境；唯一要写 C 的地方是 GPIO MMIO→虚拟引脚映射 patch（约 200-400 行）。

# v4.3 验收修复（DSH，2026-11-22）

> 验收 ZCode v4.2/v4.3 时实测出 7 个问题，全部已修并复验。改动集中在 `src/sim.js`、`src/sim-py-worker.js`、`src/app.js`。

## 1. 仿真时钟改为定时器驱动（原 rAF 被节流）

`tickLoop` 从 `requestAnimationFrame` 改为 `setInterval(tickLoop, STEP_MS)`（`STEP_MS = 20`），并按真实墙钟补步：

```js
let steps = Math.floor((now - lastTs) / STEP_MS);
if (steps < 1) steps = 1;
if (steps > MAX_CATCHUP) steps = MAX_CATCHUP;   // 6 步上限，防页面挂起后暴冲
lastTs = now;
```

`start()` 里先同步跑一次 `tickLoop()` 再挂 interval；`stop()` 与 `tickLoop` 的 catch 分支都 `clearInterval(timer)`。
**实测**：2 s 涨 100 tick（49.75 步/秒）→ 12 s 涨 600（50 步/秒，GPIO2 翻转 66 次）→ 32 s 涨 1600，无衰减、无 done/error。

## 2. Python `time.sleep` 改 async（原忙等阻塞消息队列）

`sim-py-worker.js` 新增 `wrapAsync(code)`：把 `time.sleep(` / 裸 `sleep(` 换成 `await asyncio.sleep(`，整段缩进包进 `async def __lab_main():`，用 `py.runPythonAsync` 执行；语法检查失败的代码回退同步 `py.runPython`。另加 `stopFlag`，`cmd:'stop'` 时置位。

**坑**：初版写 `import asyncio as _lab_asyncio` 但代码体里是 `asyncio.sleep` → `NameError: name 'asyncio' is not defined`（Traceback 落在 `_pyodide/_base.py` 的 `eval_code_async`）；必须写成 `import asyncio`。

**实测**：40 次循环每 0.25 s 读一次 ADC，中途电位器 80%→10%→90% → 串口 `adc 3276 / 410 / 3686`，读数实时跟随。

# v4.4 增量交接（ZCode 第五批，2026-11-22：Pyodide file:// 离线适配）

> Python 模式现在 **file:// 双击可用**：pyodide 全部运行时部件（wasm/stdlib/asm.js/loader/lock）+ Worker 源码打包成 `vendor/pyodide/pyodide-embed.js`（17.2MB，base64 内嵌），file:// 页面 script 标签正常加载（不受 CORS），主线程动态按需加载 → Blob Worker + fetch/importScripts 双补丁。改动文件：新增 `py_embed_gen.py`（项目根，生成器）、`vendor/pyodide/pyodide-embed.js`（生成产物）；`src/sim-py-worker.js`（setupEmbedPatch/boot 双模式）；`src/app.js`（ensureEmbed/pyRun file:// 分支/Blob Worker 注入）。

## 1. file:// Python 模式启动流程

pyRun handler（async）→ `LabSim.start()`（渲染循环先行，串口重置在此步）→ file:// → `ensureEmbed()` 动态加载 embed script → Blob Worker（源码 = `self.__embedData=JSON注入 + workerSrc`）→ postMessage start → Worker `setupEmbedPatch`（fetch/importScripts 补丁）→ importScripts(blob loader) → loadPyodide（虚拟 indexURL https://pyodide.sim/，fetch patch 拦截 wasm/stdlib/lock）→ machine 层 → 学生代码。

## 2. 接手必读

1. **embed.workerSrc 是生成时刻的快照**：改 sim-py-worker.js 后**必须重跑 `python py_embed_gen.py`**（项目根目录），否则 file:// 场景用旧 worker（这是本批最大的坑，曾浪费数轮排查）。
2. **py_embed_gen.py 必须在项目根运行**（相对路径 src/vendor/…），在 src/ 下运行会找不到文件且静默用旧 embed。
3. **embed 数据经 Blob 源码注入**（self.__embedData），不经 postMessage 大对象——worker onmessage 用 `msg.embed || self.__embedData || null` 读。
4. **虚拟 indexURL（https://pyodide.sim/）**：blob worker 内相对 URL 无法 new URL；fetch patch 按文件名后缀拦截（pyodide.asm.wasm/stdlib.zip/lock），importScripts patch 拦 pyodide.asm.js 转 blob URL。
5. **部署不受影响**：http/https 场景 embed 不被加载（按需动态加载仅 file:// 触发），走正常 vendor 加载（v4.3 路径）。
6. **py_embed_gen.py 曾被 Mimosa 误拦两次**（tools/ 目录 + 路径拼接模式）——放在项目根且全字面量路径后通过；改它时若被拦，先 grep 磁盘文件确认是否真有 ../（本次为误报）。
