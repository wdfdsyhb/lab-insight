## 二、数据流与联动关系（重要）

- **解析管线**：`doParse` → 大数据（>2 万行）走 `LabEngine.parseAsync`（Worker），小数据同步；解析完成后 `afterParse → refreshDerived` 在主线程统一计算统计/结论（口径切换/合并/换算共用同一后处理，Worker 只承担 parse）。
- **采集联动链**：`setupSerial.handleLine` 每 150ms → `updateLiveChart` → `updateSerialMetrics` → **`LabDashboard.update(liveSeries, liveKeyOrder, spikeKeysNow())`** → **`LabBench.updateFromSeries(...)`**（实验台打开时）。两个消费方都吃同一份 `liveSeries`（key → {label, data:[{x,y}]}）。
- **3D 场景数据源**：galaxy 直接读 `state.ds`（含 outliers Set 与 state.events 石碑）；bench 读采集的 liveSeries。两个场景退出时都销毁 renderer 与监听，不影响主图实例。
- **指纹与分享**：指纹输入 = `原始数据文本 + JSON.stringify(state.ops)`（顺序敏感）；分享 payload = {text, opts, reportInfo}。两者都以 `state.pending.text` 为数据源头，Excel 来源（aoa）没有原始文本，指纹/分享会提示改用复现包或重新导入。

## 三、各模块注意事项（接手前必读）

1. **engine-worker.js 用 importScripts('parser.js')**——Worker 的相对路径基于 worker 脚本 URL，所以三个文件必须在同一目录（当前都在 src/ 与 dist/ 各一份，OK）。
2. **file:// 下 Worker 自动回退**：`LabEngine._workerBroken` 置位后本会话不再尝试 Worker。部署环境（http/https）Worker 正常生效。
3. **galaxy/bench 每次打开都新建 renderer**，退出时 dispose + 移除 overlay + 移除监听；不要在页面里同时开两个（互斥由 st 单例保证）。
4. **虚拟仪表盘按通道序号分配仪表类型**（第 1 通道温度计、第 2 表盘、第 3 数码管），通道语义未知时用的是滑动范围归一化，不是物理量纲——改仪表语义时改 dashboard.js 的 build/update 函数对。
5. **复现包指纹与"只算当前指纹"的输入必须一致**：都用 `rawTextOf()`（pending.text，Excel 用 aoa 转 TSV）+ `state.ops`。如果以后改流水格式（pushOp 的文案格式），指纹会全量变化——属预期，验证双方用同一版本即可。
6. **three.min.js 用 r149 UMD**（全局 THREE），不要混用 ESM 版本。
7. **对比组列序错位（v3.0 遗留 P1）已修（2026-11-21 验收轮）**：renderCompareCols 的 option value 改为存列名，renderCompareChart 每组按 `ds.columns.find(c => c.name === colName)` 取各自 index。实测 A 组 temp/humi/press、B 组 humi/temp/press，选 humi → A 首点 61.98、B 首点 70.0（修前 B 得 30）。同期修掉两处：仪表开关 `dashOn` 跨函数不可见（改 state.dashOn）、galaxy.js 用 `window.state` 读写 hunterVerdicts（state 是顶层 const，改 `typeof state !== 'undefined'` 探测）。
