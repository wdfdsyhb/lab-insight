# 需求说明书 v2.1 增补：体验与导出增强

> 这是第三批小改动（v2.1），四件事，都是体验向的，不加新页签。**v1 + v2 已有的功能一条都不能改坏**。不清楚先问我。

## 总原则

- 依旧纯前端、本地计算、不依赖外部 API。
- 新增内容小步嵌入现有页签，不新增页签，不动现有架构。
- 每完成一件，在 `docs\CHANGELOG.md` 记一笔。
- 下面写的元素 id 和文案是验收依据，**照着用，别改名**。

## 改动一：导入页三步引导

- 「导入数据」页签顶部（页标题之下、第一张卡片之前）加一条三步引导横幅，容器 id=`guide-steps`，文案：`① 导入数据（或点下方示例）  ② 预览与分析  ③ 一键生成报告带走`
- 样式克制：浅底色圆角条、蓝青点缀三步序号，别做成大色块。
- 解析成功后，横幅下方出现按钮「下一步：查看数据预览 →」，id=`guide-next-btn`，点击跳转到数据预览页签。
- 已有数据再次导入时横幅保持显示，不遮挡操作。

## 改动二：导出增强

**图表导出 PNG（三处）**：

| 位置 | 按钮 id | 下载文件名 |
|------|---------|-----------|
| 智能分析主图表卡片 | `export-chart-png-btn` | labinsight-analysis-<时间戳>.png |
| 滤波对比图 | `export-filter-png-btn` | labinsight-filter-<时间戳>.png |
| FFT 图 | `export-fft-png-btn` | labinsight-fft-<时间戳>.png |

- 实现：`canvas.toDataURL('image/png')` → 创建 `<a download>` 触发下载。不引新库。
- 图表还没渲染时按钮点了给友好提示（如"请先加载数据"），别报错。

**报告统计表导出 LaTeX**：

- 「生成报告」页签导出按钮行（导出 .txt/.md/.PDF 那排）加按钮「复制 LaTeX 统计表」，id=`export-latex-btn`。
- 把统计表转成 LaTeX `tabular`：列为各数值通道，行为 最大值/最小值/均值/标准差/极差/漂移量，含 `\hline`、`\begin{tabular}`、`\end{tabular}`。
- 点击后先尝试写剪贴板（file:// 下可能被浏览器限制）；**无论成败**，按钮下方都展开一个只读 textarea，id=`latex-output`，显示完整 LaTeX 源码，让人手动全选复制。

## 改动三：大数据量兜底

1. 解析行数 > 20000 时，解析反馈区先显示黄色提示："数据量较大（N 行），解析可能需要几秒，请稍候"；完成后追加 "解析完成：N 行，耗时 X.X s"（沿用现有 parse-feedback 区域样式，加个黄色变体）。
2. 图表数据点 > 5000 时自动降采样：用 **LTTB（Largest-Triangle-Three-Buckets）**算法把显示点数压到 ≤5000（自己实现，30 行左右），图上方显示提示条 id=`chart-downsample-note`，文案含"降采样"和 "N → M 点"（如 `数据量较大，图表已降采样显示（22000 → 5000 点）`）。
3. **统计卡片、异常检测、结论、报告、滤波、FFT 一律仍基于完整原始数据计算**，降采样只影响画图，一条数据都不丢。
4. 文件 > 5MB 时，选中文件后立即提示"文件较大（X.X MB），解析需稍等"。

## 改动四：色盲友好色板 + 统计口径标注

1. 把 `app.js` 顶部的 `PALETTE` 常量（现在在 app.js:27）换成 Okabe-Ito 色盲友好色板，保持蓝为首色、和站内主色协调：
   `['#0072B2', '#E69F00', '#009E73', '#CC79A7', '#56B4E9', '#D55E00', '#999999', '#F0E442']`
   - 毛刺/异常点的红色高亮**保持不变**（语义色，不属于系列配色）。
   - 全站图表（分析图/滤波图/FFT/校准图表）统一吃这个色板。
2. 统计口径标注（两处）：
   - 每张统计卡片加 `title` 悬浮说明（如标准差卡片：`标准差为样本标准差，分母 n-1`）。
   - 统计卡片网格下方加一行小字口径说明，id=`stats-caliber-note`，文案**一字不差**：

   `统计口径：标准差为样本标准差（n-1）；漂移量 = 末值 − 初值；极差 = 最大值 − 最小值；均值 = 算术平均；异常点判定：稳健 z 分数（基于 MAD）> 3.5 或偏离中位数超 4×MAD`

   （这句和 analysis.js 里的实际算法一致，不许改成别的口径。）
